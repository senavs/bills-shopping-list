# Search (lists & items) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Search lists by name on the dashboard (filter in place) and search items inside a list through a search screen whose results open the item editor.

**Architecture:** Pure matching in `src/lib/search.ts`. Dashboard holds `searchOpen`/`query` state and filters what it already renders. A new `ItemSearch` full-screen overlay lists matching items. `ListDetail` opens it and routes `onSelect` to its existing `setEditingItem`.

**Tech Stack:** React 18, TypeScript, Tailwind, Vitest + Testing Library (happy-dom).

**Spec:** `docs/superpowers/specs/2026-11-21-search-design.md`

## Global Constraints

- Every user-facing string goes through `useLanguage().t`, with the key in both `src/i18n/en.ts` and `src/i18n/ptBR.ts`.
- Dark mode: use the semantic classes (`bg-bg`, `bg-surface`, `bg-fill`, `text-ink`, `text-muted`, `text-accent`, `bg-hairline`), which already adapt.
- No data model, sync or `localStorage` changes.
- Before done: `npx tsc --noEmit` and `npx vitest run` pass.

## Review Focus

1. A query with accents or different case ("PÃO", "pao") matches "Pão". Covered in Task 1.
2. A query of only spaces behaves like an empty query, not like "no results". Covered in Task 1.
3. An item inside a **collapsed** section still appears in the item search. Covered in Task 3.
4. Closing the dashboard search restores the full list. Covered in Task 2.
5. Selecting a result opens the editor with **that** item's values. Covered in Task 4.
